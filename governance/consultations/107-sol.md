## What the reviewer found sound

The egress chain (`lstat`, `O_NOFOLLOW`, `fstat`, ino+dev recheck, link-count
rejection, byte cap, exclusive destination creation); `ingress_symlink` genuinely
reaching phase 2, with the content and `islink` assertions closing the
`FileExistsError` ambiguity the operator had flagged; exclusive directory
creation with 0700 staging; and `mem_limit` being declared unclaimable rather
than quietly assumed.

## Three defects the review did not name, found while fixing it

- `_sweep_stale_runs()` carried the docstring "Called once at startup" and had
  no call site.
- The new run lock was placed in world-writable `/tmp`, where uid 601 could
  write PID 1 into it and refuse every subsequent run, permanently and silently.
- The sweep ran before the lock was acquired, so a second launcher would delete
  the live workspace of the first.

And after those: the suite reported 7/7 with two hollow confirmations, because
the hardened ingress created destinations `0600` owned by uid 501 and the worker
could not read its own `config.json`. The payload swallowed that and reported
"cannot assess", which the host counted as BLOCKED. Absence of evidence recorded
as evidence — the same shape as the findings above, one layer down.

Payloads now report three outcomes (allowed / blocked / unavailable) and any
`unavailable` in a mandatory check fails the canary.

## Raw review

## Ranked findings

### 1. High: `no_network` can pass when Seatbelt networking is a no-op

**Code:** `core/payloads/no_network.py:18-45`, `core/canaries/no_network.py:34-48`

**Executable failure:** Run the suite on a host with no default route, broken DNS, or an outbound firewall, while removing or neutralizing `(deny network*)`. Both the connection to `1.1.1.1:443` and DNS lookup fail for environmental reasons. The orchestrator sees only `succeeded == False` and confirms `no_network`.

**Consequence:** `policy.json` claims `no_network` without establishing that Seatbelt caused the refusal. Network access can later become available when routing or DNS changes.

**Required fix:** Start local TCP, UDP, and IPv6 listeners outside the sandbox, prove the endpoints are reachable without Seatbelt, then require the sandboxed attempts to fail. Require an exact mandatory check set rather than accepting whatever checks appear in `result.json`.

### 2. High: The write half of `fs_confinement` is proved only by Unix permissions

**Code:** `core/payloads/fs_confinement.py:85-91`, `core/canaries/fs_confinement.py:59-95`

**Executable failure:** Replace the workspace-only file-write rule with an accidental broad `(allow file-write*)`, while retaining read restrictions. The payload tries to create:

```text
/usr/local/var/jcode-runs/runs/outside_canary_test
```

The parent is `0771 root:wheel`, so uid 601 receives a DAC denial even though Seatbelt would allow the write. All read checks can remain blocked and `write_inside` succeeds, so the canary confirms `fs_confinement`.

**Consequence:** The worker can write to Unix-writable locations such as `/private/tmp`, while the policy still claims filesystem confinement. A surviving process could then interfere with future supervisor operations outside its workspace.

**Required fix:** Have the owner create a unique, world-writable target outside `WORKSPACE`, then require the worker's write or modification to fail and verify the content host-side.

### 3. High: One `pkill` pass cannot terminate a process tree that is still forking

**Code:** `core/backends/macos_seatbelt.py:227-281`, `core/backends/macos_seatbelt.py:411-425`, `core/canaries/tree_kill.py:82-107`

**Executable interleaving:** Maintain several worker processes continuously forking replacements. `pkill` enumerates a non-atomic process-table snapshot. After a parent is enumerated but before it receives SIGKILL, it forks a child that was not in the snapshot. `pkill` kills at least one listed process and exits 0 with empty stderr, so `kill_all()` returns `ok=True`, while the new child survives.

The `tree_kill` canary uses a quiescent daemon that never forks after writing its PID, so it cannot detect this failure.

**Consequence:** The wall-clock watchdog reports a successful kill while adversarial worker code remains alive, consuming CPU, memory, or process slots and racing cleanup.

**Required fix:** Repeatedly enumerate and kill until the worker uid is observed empty for a stable interval, with a hard failure if quiescence is not reached. A per-run uid or OS job primitive is preferable because enumerate-and-kill remains inherently racy.

### 4. High: A timed-out run kills every concurrent worker run

**Code:** `core/backends/macos_seatbelt.py:247-281`, `core/backends/macos_seatbelt.py:411-425`, `core/worker_kill.sh:20`

**Executable input:** Run jobs A and B concurrently. Job A sleeps for more than 60 seconds, consuming no CPU limit. A's watchdog executes:

```sh
pkill -9 -u _jcode_worker
```

This kills B and every other process using uid 601, not merely A.

**Consequence:** Any confined worker can terminate unrelated runs on demand. The diff contains no serialization lock or per-run process identity preventing this cross-run denial of service.

**Required fix:** Use a distinct uid or killable OS job identity per run. If concurrency is intentionally forbidden, enforce that invariant in this code before launching rather than depending on an unstated external caller guarantee.

### 5. High: Cleanup is bypassable and already leaks directories on successful canary runs

**Code:** `core/backends/macos_seatbelt.py:397-405`, `core/backends/macos_seatbelt.py:433-441`, `core/canaries/tree_kill.py:110-124`

Two deterministic paths skip cleanup:

1. `teardown=False` returns before `shutil.rmtree`, and `tree_kill` never removes its inner workspace.
2. `symlink_egress` deliberately causes `_copy_egress()` to raise `PermissionError`; that exception occurs before `shutil.rmtree`, and the canary treats it as success.

A worker can amplify this by creating many files up to the per-file limit and then making `result.json` a symlink. The expected refusal prevents cleanup, while `disk_quota` is explicitly unavailable.

There is also a race in the nominal cleanup path: a surviving same-run process can create another entry between `rmtree`'s enumeration and final `rmdir`. `ignore_errors=True` converts `ENOTEMPTY` into reported success.

**Consequence:** Persistent `0777` run directories, run-id pinning, and deliberate disk or inode exhaustion.

**Required fix:** Put cleanup in an outer `finally`, revoke worker access before deletion, terminate and verify the worker is quiescent, and treat cleanup failure as a surfaced backend failure. Add explicit cleanup for `teardown=False`.

### 6. High: `run_id` traversal reaches owner filesystem operations, and the wrapper validation is multiline-bypassable

**Code:** `core/backends/macos_seatbelt.py:337-370`, `core/worker_exec.sh:19-39`

`run()` documents a regex requirement but never enforces it before using `run_id` in `os.path.join`, `mkdir`, ingress writes, and `chmod`.

A direct input such as:

```python
run_id = "/private/tmp/jcode-owned-stage"
```

makes the owner create, populate, and chmod that directory before the wrapper rejects the slash.

The wrapper is not a complete backstop because `grep` validates lines rather than the entire argument. For example:

```text
../../../../../private/tmp/
OK
```

contains a matching `OK` line, so `grep -qE` succeeds. The backend resolves this traversal and creates `/private/tmp/<newline>OK`; the wrapper resolves the same path and supplies it as `-D WORKSPACE=...`, moving the Seatbelt workspace outside `_RUNS_DIR`.

**Consequence:** Model-influenced host input can make the owner plant files under any existing owner-writable parent, grant a Seatbelt workspace outside the trusted run tree, and combine this with finding 5 to preserve it.

**Required fix:** Apply Python `re.fullmatch(r"[A-Za-z0-9_-]{1,64}", run_id)` before any path operation. In the wrapper, reject newline-containing arguments and use whole-string shell validation rather than line-oriented `grep`.

### 7. Medium: `pid_limit` can confirm global exhaustion instead of the configured RLIMIT

**Code:** `core/canaries/pid_limit.py:44-93`, `core/worker_exec.sh:56-60`, `core/policy.json:20`

**Executable failure:** Suppose `ulimit -u 64` returns success but is ineffective. A stale uid-601 workload consumes enough of macOS's global per-uid process ceiling that only 50 slots remain. The payload forks fewer than 100 children and receives `EAGAIN`. The canary accepts this as proof of `RLIMIT_NPROC`, then `kill_all()` removes the stale processes.

**Consequence:** The suite confirms `pid_limit`, although a clean future run can fork up to the much larger system per-uid ceiling. The canary also accepts any count from 1 through 100 while policy specifically declares 64.

**Required fix:** Report and validate `resource.getrlimit(RLIMIT_NPROC)` inside the payload, establish a zero-worker baseline before launch, and verify the observed boundary against `policy.json`.

### 8. Medium: Claimed capabilities absent from `_CANARY_ORDER` are automatically confirmed

**Code:** `core/launcher.py:13,76-96`

**Executable input:** Add `"mem_limit"` or `"new_capability"` to `claimed_capabilities` without adding it to `_CANARY_ORDER`. The suite iterates only `_CANARY_ORDER`; the new claim is never tested or discarded. It remains in `claimed`, so `surviving == total` and the launcher reports every capability confirmed.

**Consequence:** The central fail-closed capability contract can be widened with green output and no canary at all.

**Required fix:** Iterate over every claimed capability and fail if no registered canary exists. Also require exact equality between the claimed set and the canary registry.

## Sound portions

- The egress `lstat`, `O_NOFOLLOW`, `fstat`, inode/device recheck, link-count rejection, size cap, and exclusive destination creation correctly close the named symlink and substitution attacks.
- `ingress_symlink` genuinely reaches phase 2 only after phase 1. The target-content comparison plus final `islink` assertion closes the “regular file already existed” ambiguity, although `O_EXCL` alone is sufficient for that refusal.
- Exclusive run-directory creation and staging at `0700` prevent a correctly confined stale worker from modifying a new directory during staging. Reusing an existing run id is safely refused.
- `symlink_egress` establishes its specific capability. Its failure is cleanup, not the symlink judgment.
- `mem_limit` is plainly unclaimable, and nothing in this diff treats memory containment as available.
- Determining every allowance inherited from `(import "system.sb")` would require inspecting `/System/Library/Sandbox/Profiles/system.sb`; I did not fetch it because it is outside the supplied diff.
