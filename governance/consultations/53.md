### 4. Failure mode invisible during a long autonomous session

The dominant residual failure mode is the one the text now names: a solo operator fabricates or steers a consultation, commits a well-formed artifact, and CI goes green. The constitution's defense is detectability-in-history, not prevention, and it says so. The *new* failure mode this diff introduces is subtler: **stale-approval laundering in reverse is prevented, but approval churn is not**. Because any post-consultation edit invalidates the artifact (as this very PR demonstrates), an operator under time pressure will be tempted to regenerate consultations repeatedly until one matches, and the "every consultation attempted ... is committed, including abandoned ones" rule is enforced by nothing mechanical — an omitted abandoned attempt leaves no trace. During a long unattended session, nobody would notice a consultation that was run, came back REJECT, and was never committed, followed by a fresh "first" consultation after a cosmetic re-diff. The 42-attempt-sol.md file shows the norm being honored once; nothing makes it load-bearing. This is a known, disclosed gap ("prose is not enforcement" applies to the attempt-logging rule itself), not grounds for rejection of this diff, but it should be tracked as the next hardening target.
