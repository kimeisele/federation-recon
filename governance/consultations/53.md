## Response (verbatim)

This PR adds CI enforcement of the consultation requirement defined in
`CLAUDE.md` → Delegated judgment. The change is not self-serving in a harmful
way — it constrains the operator rather than expanding its authority, by making
a previously-prose-only requirement mechanically enforceable.

### 1. Is the change self-serving?

No. The change adds a gate that the operator must satisfy. It makes the
operator's own compliance checkable by a deterministic script, removing the
discretion the old prose-only rule left open. The operator cannot merge a PR
touching constitutional files without a mechanically-verified consultation
artifact. This is the opposite of self-serving: it is self-binding.

### 2. Riders?

None. The diff is focused: one new library file, one edit to `ci-checks.sh` to
wire it in, one test file, and one consultation artifact. No unrelated changes
are bundled.

### 3. Real constraint or disclosure?

Real constraint. The check:
- Runs deterministically in CI (`bash scripts/ci-checks.sh`)
- Requires a committed file at a predictable path
- Verifies reviewer, provider, verdict line, and raw diff hunk headers
- Cannot be satisfied by an artifact that merely mentions filenames
- On REJECT, requires a second APPROVE from a different artifact

This is the mechanical enforcement the repository's own position ("prose is not
enforcement") demands.

### 4. Failure modes

- **The gate cannot verify independence of weights.** It checks that an artifact
  names a reviewer and provider, but cannot verify the consultation actually
  happened with a different model. The operator could fabricate an artifact.
  Mitigation: this is inherent — a local gate cannot verify an external model
  call. The gate makes fabrication detectable (committed, diffable, timestamped
  in git history), which is the most a deterministic check can achieve.

- **PR number detection is fragile.** The gate extracts the PR number from
  `CONSULTATION_PR_NUMBER` env var or branch name digits. An oddly-named branch
  (e.g., `fix/something`) would result in no PR number and the gate would be a
  silent no-op. Mitigation: CI sets the env var explicitly. Local runs without
  PR context are expected to be no-ops.

- **The gate uses `origin/main...HEAD` for diff computation.** If a branch has
  no remote tracking, the diff may be empty. Mitigation: CI always has
  `origin/main`.

### 5. Founding intent drift

This change strengthens, not weakens, the founding intent. `CLAUDE.md` already
states "Prose is not enforcement." #42 added the consultation requirement as
prose. #43 (this change) makes it a gate. The trajectory is toward more
enforcement, not less.

### 6. Other observations

- The gate follows the same pattern as the existing manifest-gate: a small
  focused library sourced by `ci-checks.sh`, parsing its source of truth rather
  than hardcoding a copy.
- The tests cover every failure condition with specific assertions about the
  error message.
- The gate does not acquire new dependencies (uses grep, sed, git, python3 only).

verdict: APPROVE
