## Answers

- (b) Same-second concurrent session on the shared host log emitting an identical `model:/endpoint:` tuple defeats the ambiguity check silently (dedup by set). Admitted in the caveats.
- (c) In profile mode the `prv:openrouter` tag is never inspected — verification rests entirely on the endpoint string, so an openrouter-fronted route with the expected endpoint passes as "direct". Given the endpoint is the paid thing, this is defensible, but the "direct DeepSeek route" claim in review materials overstates what is measured: what is verified is *model + endpoint*, never the upstream provider.

**1b.** No self-loosening found. Legacy `-p/-m` path preserved verbatim; every new branch fails closed (missing endpoint → refuse; missing probe → refuse; mismatch → exit 1 before mutation; ambiguous → exit 1). The `|| true` on `usage-record.sh` pre-exists in shape and the runner-side cost-record check is the compensating control.

Consistent, though the stub implies real jcode logs an `auth:` field — worth confirming the real log doesn't carry a live key into `builder_provider.txt` (the regex doesn't capture it, so low risk). "Full gate passed" — **not verifiable here**, treated as unverified.
